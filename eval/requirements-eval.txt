# Eval harness dependencies — installed in their OWN environment, NOT into the
# api service image.
#
# WHY separate: ragas pins langchain-core to the 0.3 line, which conflicts with
# the langchain-core>=1.3 that LangGraph (the agent service, apps/api) requires.
# The two cannot share a venv. This is fine: RAGAS only exercises the retrieval
# path (QAService), never the LangGraph graph, so the split is clean. The
# deterministic gate (run_golden_eval.py) and the fact-checker eval
# (eval_factchecker.py) have NO such conflict and run against the service image.
#
# Install (example, against the built api image's code at /app):
#   pip install -r eval/requirements-eval.txt
#
# Pins chosen to resolve cleanly together on Python 3.11.
# ragas 0.2.15: 0.2.6 had a faithfulness-metric bug ('StringIO' has no
# attribute 'sentences') that returned NaN; 0.2.15 computes it correctly.
ragas==0.2.15
langchain-openai>=0.2,<0.3
langchain-community>=0.3,<0.4
# fastembed + pandas are pulled transitively but declared for clarity: fastembed
# provides the bge-small embeddings (same model retrieval uses); pandas backs
# ragas result.to_pandas().
fastembed>=0.4,<0.5
pandas>=2.0
